## 11:05 — S5 (head_to_head_comparison) submitted to O2, agent-driven SSH

**Goal.** Resolve the previous entry's open question (S5 needs a real, non-pilot run; no O2 access
previously assumed available) by having the agent SSH into O2 directly, diagnose blockers, and
submit the real Slurm job.

**What happened.**

1. **Wedge recovery.** Found and killed a hung `ssh dma12@o2.hms.harvard.edu` from an earlier
   attempt (dead-socket-but-alive process, `lsof` showed the TCP connection `CLOSED` while the
   process stayed running — laptop-sleep-induced). Documented the pattern (never block on a raw
   `ssh`; background + poll + hard-kill).
2. **SSH environment archaeology.** Non-interactive `ssh host 'cmd'` looked completely broken
   (`module`/`Rscript` "not found", scripts silently producing zero output). Root causes: the
   account's `~/.bash_profile` is `exec zsh` (discards anything passed via `bash -l`); `~/.bashrc`
   guards on `[ -z "$PS1" ] && return` (skips `module load` for non-interactive shells); Lmod needs
   `source /etc/profile` first or `MODULEPATH` stays undefined. Actual repo path on O2 is
   `~/doubletree`, not `~/global-scholars/doubletree` as the study's own `README_O2.md` claims.
3. **Duo/2FA, corrected twice.** First wrongly concluded key-based auth bypassed Duo entirely
   (a run of one-off commands all returned in a few seconds with no visible prompt) — the user was
   silently approving a push per command the whole time. Set up an SSH `ControlMaster` to fix it;
   confirmed via `ssh -v` that a mux-reused session still triggered a fresh Duo push with *zero*
   authentication in the log — HMS gates Duo on session-open (exec/subsystem channel), not on the
   TCP/crypto handshake, specifically to prevent multiplexing from bypassing 2FA. `scp` is equally
   gated (4 separate file transfers cost 4 pushes). The real fix: batch every logical step into one
   script, run via one `ssh host 'bash -s' < script.sh` — confirmed empirically to cost exactly one
   Duo push regardless of how much the script does.
4. **Two real, unrelated bugs surfaced and fixed while getting `quick_test.sh` green:**
   - `cli >= 3.4.0` reserves any `{.foo}` glue expression starting with a dot for its own inline
     styles, breaking a `for (.arg in ...)` pattern that used `{.arg {.arg}}` to both style *and*
     interpolate the loop variable. Fixed by renaming the loop variable to `arg_name` in all four
     affected studies' `code/common.R` (`head_to_head_comparison`, `single_tree_corollaries`,
     `honest_inference_sparsity_failure`, `partition_recovery_clt`; `propensity_loss_choice` was
     already fine, it hardcodes the arg name).
   - `optimaltrees` (treefarmr) on O2 lacked `bisect_lambda_to_budget()`, which `doubletree`'s
     `DESCRIPTION` requires (`>= 0.4.1`). Root cause: the local dev machine's `optimaltrees`
     checkout was 39 commits ahead of its own `origin/main` on GitHub — never pushed. Pushed
     `df6548d..d07397c` to `denisagniel/treefarmr` (user-confirmed: GitHub `origin` is canonical,
     not the `gitlab`/`code.rand.org` remote also configured there), then `git pull` + reinstall on
     O2 picked it up.
   - Along the way, `.libPaths()` proved non-deterministic across back-to-back `ssh` sessions on
     the same login node (same commands, same module loads — sometimes a given personal library
     path was listed first, sometimes not listed at all), which briefly made the reinstall look like
     it "didn't take." Fixed by explicitly pinning `R_LIBS_USER` and `R CMD INSTALL --library=...`
     rather than trusting the ambient default, after clearing both candidate library directories.
5. **`quick_test.sh` passed end to end** (`optimaltrees 0.4.1`, `doubletree 0.0.0.9000`, R6 block:
   2/2 replications, 0 failed, coverage 2/2). `DRY_RUN=1 launch_all_simulations.sh` confirmed the
   134-task/6-array sizing. **Real run launched**: run id `20260918-130255_88ba1bd` (git SHA

6. **Wrote up the whole SSH/Duo/Lmod/`.libPaths()` operating-notes set** as
   `~/RAND/tools/O2_SSH_GOTCHAS.md` (moved there from an initial doubletree-repo-root draft, at the
