# Session Notes — 2026-09-23

## 09:00 — S5 unblocked on O2: the Sep-18 mass cancellation root-caused

**Goal.** Find out why S5 run `20260918-130255_88ba1bd` (`head_to_head_comparison`, 6 arrays,
134 tasks) died three seconds after starting, and get the study running.

**What happened.**

1. **The Sep-18 diagnosis in this repo's notes was wrong.** That entry attributed the failure
   to the inherited-`module` mechanism. `sacct` had already refuted it and it was misread:
   `CANCELLED by 0` (root) with `ExitCode 0:0` means the script never errored, whereas a
   failed `module load` under `set -e` would give `FAILED` with a non-zero code and a
   non-empty `.err`. There were **zero** `.out` and `.err` files.

2. **Real cause: `sbatch --export=ALL,KEY=value`.** O2 cancels the batch step by root within
   1–3 s — `.extern` completes, `.batch` cancelled, `ExitCode 0:0`, `Reason None`, no output
   at all. Isolated by submitting one payload five ways on three nodes: the combined form
   cancelled every time; plain `--export=ALL` and no `--export` completed; shell-exported
   variables plus plain `--export=ALL` completed **and** delivered the variables. Ruled out
   independently: script-file vs `--wrap`, output to subdirs and to `/n/scratch`, `--mem=2G`,
   `module load`, outbound `curl`, node health, account standing.

   `launch_subset.sh:152` used exactly this form, as did the scaffold it came from.

3. **A second, independent defect, found only by trying to submit.** `launch_subset.sh` runs
   on a login node and calls `Rscript` in its preflight. `module` is a bash function Lmod
   `export -f`s into the environment, so it is inherited — present for a human at a prompt,
   absent under `ssh host 'bash -s'`. The existing `if command -v module` guard silently
   skipped because `module` was *undefined*, not unloaded, so agent-driven submission died at
   `Rscript: command not found` while the same command worked when typed by hand. Fixed by
   sourcing `lmod.sh` before strict mode, then loading the toolchain.

4. **S5 R1 runs.** Array `54215944`: all 5 tasks `COMPLETED 0:0` (7:50–14:54, MaxRSS ~350 MB
   against 4 G), 5 shards, **zero** non-empty `.err`,
   `1000 reps x 5 arms = 5000 rows, 0 failed rep(s)`, `finished with status 0`.

5. **Two O2 facts settled in passing.** Compute nodes **do** have outbound egress
   (`curl` → 200), and `--mail-type` works (completion mail arrived). Both were open
   questions for the unattended-pipeline design.

6. **`run_simulations.slurm`, `profile.slurm`, `resize_sizing.R`, `submit_per_method.sh`,
   `submit_tier2.sh`, `smoke_autosubmit.sh`** all carried the fatal export form or the
   missing bootstrap; all fixed, committed and pushed to GitHub (`5d71a5c`).

**Decisions.**
- Instruction text counts. `resize_sizing.R`'s `stop()` messages and `profile.slurm`'s header
  comments *told the reader to run the fatal command*; reworded to `VAR=value sbatch
  --export=ALL …`.
- `prep_offline.sh`-style nested `sbatch` inside a `--wrap` string was hand-edited rather
  than machine-transformed — two levels of escaping, and a corrupted quote would reproduce
  the same zero-output cancellation it was fixing.

**Mistake worth recording.** The first attempt to reconcile O2 with git left the checkout
**worse**: I discarded the hand-written fixed files expecting `git pull` to replace them, but
the pull aborted on unrelated uncommitted O2-local edits (`common.R` in three studies), so O2
briefly sat at `88ba1bd` with the *old broken* versions. Repaired by stashing the blockers and
pulling to `5d71a5c`, verified live (`bootstrap:2`, `fatal-form(exec):0`). The stash proved
redundant — all four `common.R` files were byte-identical to what git already had. Lesson:
stash, do not discard, and check for other dirty files first.
