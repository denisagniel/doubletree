   finished. The code's own comment on the discard path states the design intent directly:
   "Never cherry-picks survivors. A partial `<ingest_id>` invites someone to pin an ingest that
   is silently missing a dataset." `.smi_newest_ingest_path()` filters strictly to
   `complete == TRUE` ingests, so an in-progress run is invisible to `smi_read()` regardless of
   how many individual files it has already converted internally. Confirmed `06_ingest.R` calls
   `smi_ingest()` exactly once for the whole run (not once per file), matching the "16/64 in
   24h, ~3 more days" framing in smidata's own session notes as one batch's progress, not 16

   touches anyway (confirmed by direct grep: it appears exactly once in the whole `application/`
