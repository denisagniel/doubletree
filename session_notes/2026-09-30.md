## 11:20 — correction: `diagnostics` is a reported flag, not an estimator fallback

**What was wrong.** The first pass above, and the code/docs it produced, drifted into framing the
resolved `diagnostics` rule as licensing a *substitution*: "when the licence fails, report
`estimate_att_crossfit()` instead of `estimate_att()`." The PI corrected this directly: **"we
never fall back to cross-fitting. No silent fallbacks."** That framing contradicts
`07_estimate_att.R`'s own pre-existing, unchanged design (stated in its header before today):
`estimate_att()` is always the flagship (per `config_estimator`), `estimate_att_crossfit()` is
always its companion, both are always reported alongside their discrepancy, and the script never
auto-switches between them — auto-switching would be the data-dependent post-selection inference
the paper does not analyse. My printed "Licence FAILS" message and the `_config.R`/README prose
had reintroduced exactly the fallback the file's own header disclaims.

**Fix.** `certified_e && certified_m0` is a **reported diagnostic flag on the flagship result**,
nothing more: it says whether this proxy supports grid-exact sparsity for `estimate_att()`. It
does not change which number is "the" estimate, does not trigger any substitution, and a failed
licence is a signal to scrutinize `07`'s already-reported discrepancy in the write-up — not an
instruction to swap in `estimate_att_crossfit()`'s number. Reworded the licence-print block in
`07_estimate_att.R`, the `note` in `application/_config.R`'s `diagnostics` entry, `07`'s header
comment, and the `README.md` decision-table row accordingly. Re-parsed all four `.R` files and
re-ran `application/run_tests.R` — unchanged 192 passed / 4 failed (the pre-existing
`optimaltrees.so` block, confirmed via `git stash` comparison, both before and after this
correction).
