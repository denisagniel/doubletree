## First real-run errors: leaf_budget raised to 15, negative prior_cost floored

PI ran (or attempted) `01`–`06` for real and reported two things: wants
`config_leaf_budget` raised from 4 to "15 or 20" (settled on 15), and 2 patients had negative
`prior_cost` (claim reversals exceeding pre-index payments), which
`discretize_prior_cost()` refuses by design (its own abort: "a decision, not a binning
detail").

**prior_cost fix.** PI decision: floor negative values to 0 before binning, not exclude the
patients or allow signed values into the quantile grid. Registered as
`OPEN_DECISIONS$prior_cost_negative_floor` (confirmed, value `0`). New pure helper
`floor_negative_prior_cost()` in `helpers/discretize_prior_cost.R`, wired into both call sites
(`04`'s preview, `06`'s authoritative pass), each reading the confirmed value explicitly
(`confirmed_value("prior_cost_negative_floor")`) rather than hardcoding — same pattern
`03` uses for `cost_family_scope`. `discretize_prior_cost()`'s own negative-value abort is
UNCHANGED — still fires for any caller that forgets to floor first. The RAW dollar
`prior_cost` retained in `06`'s output is NOT floored, only the value fed to binning is — the
true negative net cost for those 2 patients stays visible for the methods section. Added 6
new test cases (`test-discretize-prior-cost.R`); full 48-assertion file passes.

**leaf_budget fix, and a runtime finding that blocked just setting it.** Set
`config_leaf_budget <- 15L`. Before trusting this at scale, benchmarked `estimate_att()` on
the existing 400-row Tier-0 toy fixture (same 15-column shape as the real design matrix):
**4.8s at leaf_budget=4, 94.5s at 6, still running past 5+ minutes at 15 (killed).**
optimaltrees' GOSDT-style search cost grows steeply with leaf_budget, largely independent of
`n` — the real ~250k-patient run risks discovering an infeasible budget only AFTER `03`'s
multi-hour, 171.5GB cost-streaming pass, since `07` is the last stage. Flagged this to the PI
with the numbers rather than silently proceeding; PI chose to time-box a real-data probe
before running `07` in full. Wrote `91_leaf_budget_feasibility.R`: standalone, NOT gated by
`assert_no_blocking_open()` and NOT part of the 01–07 cascade — times `estimate_att()` alone
(not the more expensive `estimate_att_crossfit()`) on the real `analytic_cohort_PROVISIONAL.parquet`
and reports elapsed time, informationally only, never as a reportable estimate. Its own
`setTimeLimit()` is best-effort only — optimaltrees is compiled C++ (Rcpp) and a long-running
call that never checks for interrupts internally won't be stopped by R's own elapsed-time
mechanism until it returns control to R. The real bound is an OS-level kill from the shell:
`timeout 900 Rscript application/91_leaf_budget_feasibility.R`.
